Before you start:

- WebDAV isolation (workflow "Test WebDAV first") runs once per session, outside this kit, before installing — snapshot `webdav.*`, suspend the three sync switches, point `webdav.url` at the test folder, and restore all four (url first of that group, sync switches last) only after this kit's `90-cleanup.js` has erased the fixtures.
- Install the xpi, confirm `-betaN`, run `diagnostics.startup()`, then `01-baseline.js`. Fixtures are `fixture-a.pdf` (17 segments, 2 pages) and `return-key/return-key.epub` (241 segments); the EPUB opens in `paginated` flow by default here.
- Window: this whole case is geometry-driven; the host must be visible for the run. If the owner left it minimized, restore it first — 2026-10-01 the numbers were identical either way (toolbar bottom 41 and the frame band 41–75 measured the same minimized and visible), but `getBoundingClientRect` under a minimized window is not the case's stated condition. `90-cleanup.js` minimizes at its end (this case's owner-set exception).
- Trusted wheel scrolls (`10-item4-keep-following.js`) target the reader's own top-level window (`reader._window`, the main Zotero window); the wheel maps 1 `deltaY` to 0.5 px on this window, and the script computes its final step from the pre-measured band instead of fixed deltas.
- `readAloud.memory` is overridden with a listed Fish voice (`fish::en/933563129e564b19a115bedd57b7406a`) before any player opens (issue #133's stale `local::af_fake`) and restored byte-for-byte after `documentVoiceChanged`, with Zotero's `reader.readAloudVoices` restored last of every pref (a chrome write of it is a voice pick to memory-sync's observer — memory is re-verified after).

Limits:

- `06-item2-split-view.js`: Zotero's own secondary-view find popup did not open live here even once the secondary PDF view's own iframe was confirmed mounted and connected (`ir._state.secondaryViewFindState.popupOpen` stayed `false` after `toggleFindPopup({primary:false,open:true})`, no thrown error). The secondary side of the case's claim is evidenced by a synthetic `.find-popup`-classed probe element appended as a real child of the live `.secondary-view` node (CSS matches it identically to a real one), cross-checked against the primary view's own synthetic-vs-real agreement first.
- `08-item4-covered.js`: PDF's `covered` (sentence-in-view.ts) is `null`, not `{0,0}`, once a session fully closes, because it is computed only when an active segment exists; EPUB's (dom-follow.ts) is not gated the same way and does read `{0,0}`. Both are reported as their own value rather than forced to agree; this is a source-level asymmetry between the two follow modules, not a defect from this fix.
- `09-item4-outside-mode.js`: the trigger that actually moves a clipped sentence is the placement scroll's own native `scroll` event (both follows evaluate on it), measured PAUSED throughout; `sawCut` can read `null` when the decision was recorded before the script's own polling started (finalReason carries it). 2026-10-01: `repositionTo`'s own auto-center kept easing past a 2.5s settle and swept the placement back (the box read `null` on a single read; the scroll landed off-target), so the box read polls 6s, the placement is held until the target sticks, and the pre-settle budget is 5s. Even so the engine can re-center a round's placement away — across three runs every round evidenced the behavior, not always in the same run.
- `10-item4-keep-following.js`: the case's Floating half ("the sentence counts as visible and following stays on") describes the pre-#153 behavior (#100's `manual.begin('wheel')`). Since c6e99a9 (#153, 2026-09-27) ANY trusted wheel disengages following in EVERY layout (pdf-follow.ts:191-192, unconditional; a resume carries `force = intent.automatic = false`, so only the explicit A — the player's `.mode` control — re-engages). The script re-engages through that control; the case's bullet was rewritten to the current design on 2026-10-01. The 2026-09-24 PASS row ran the old code.
- A run-scoped `readAloud.autoScrollMode` can read back `outside` immediately after `09-item4-outside-mode.js`'s own restore line (2026-09-24 and again 2026-10-01; cause not identified — no observer or debounced writer for this pref was found). Check and re-clear it after the script; it held after a manual clear both times.
- `13-item6-appearance-top.js`–`16`: each opens the player through `#ztts-player-toggle`, so each first ensures a closed start (an inherited open popup would be closed by the toggle, and activation would time out — hit 2026-10-01 after `11` left the EPUB player open).
- Trusted-wheel calibration and the case's absolute numbers are window-specific: 2026-09-24 measured on a 1458×949 outer window (doc bottom 912), 2026-10-01 on 1411×924 (doc bottom 887). Offsets from the toolbar bottom are the stable form.
