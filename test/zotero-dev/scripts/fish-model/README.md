Before you start:

- Build: the profile must run the release `1.16.10` (`00` throws otherwise). Install `build/Zotero-OpenReader.xpi` between `01` and `02` and prove it by the profile file's SHA-256 and the bundle's `compat/v1/models` / `ztts-fish-model`, not the version.
- Order: `00`, `01`, install, `02`, `03`, reinstall, `04`, `05` (first pane open after the last install), `06`, `07`, `08` ×3, `09`, `10`, `11`, `12`, `99`. One run at a time; `reset()` and the removal of `.tmp/zotero-dev/fish-model/snapshot.json` at the very end.
- The profile in 2026-10-16: Fish on (user value), key set, own Fish Speech address and headers, WebDAV folder on with positions sync, an owner's paused Fish player in the selected tab (closed by `07`, never reopened), a settings window open (closed by `01`). Zotero's own tiers are off, so nothing metered can answer.
- State touched: `zotero-tts.fish.{enabled,model,freeOnly,voices}`, `readAloud.volume`, `documentVoices.*`, `documentVoiceChanged`, `reader.readAloudVoices` (the reading rewrote them; `99` puts them back), `webdav.enabled`, the settings window, one fixture item and tab, the debug store, the host window (left minimized). The key is never read.
- Money: free model and 402 only (credit 0); 2 × 402 POSTs, ~13 free POSTs; the 1c.3 refusals send nothing. Never a loop.

Limits:

- **1c.5 NOT TESTABLE live**: Restore settings is only reachable through `FilePicker` (a native panel, never through the bridge); `Zotero.ZoteroTTS` and `diagnostics` expose no restore entry. Covered by `test/core/settings-backup.test.ts:154` (`'fish.freeOnly': false` → `fish.model` `s2.1-pro`, `ignored: []`): the 6 related test files (settings-backup, settings-sync, settings, fish-model-rows, fish, player-controller) run 2026-10-16 pass, 243 tests.
- The case's `Zotero.Prefs.prefHasUserValue('zotero-tts.fish.freeOnly', true)` is always false; use the name alone or the full name with `true`.
- A script-started session's output stays `suspended` on this Zotero until a trusted Shift+Space (nsITextInputProcessor, 2 presses); later sessions in the tab were already running. The synthesis checks need no clock; "the next unprepared sentence" does (`12`).
- Reading to sentence N saves a position row; erasing the fixture then adds one local tombstone (`deletions` +1, never leaves the machine; cannot be taken back through the bridge). The first `99` pass (`-p`) had no gate and switched the folder on with `deletions` +1; the revised gate (rows, loaded, local entries, shared equal) was re-run only when everything was already restored, so the "folder stays off" branch has not run.
- `Zotero.Debug.get()` starts with the error ring and system info: read the entries after the `=====` line; `setStore(true)` clears the store, so call it once.
- `10`'s first attempt stopped: the session exists before the voice list arrives (`session.voice` empty), so the Fish guard now waits up to 20 s for the voice.
- The model-gone refusal repeats at every Engine prefetch attempt (16 + 15 `Zotero.logError` entries in two ~13 s readings, `store.requests` 6 → 22); none reaches the network. 1c.3 accepts it; a long reading would fill the console.
- Two sections of the case are stale since #91, not this change: the voices placeholder (`IDs from Fish Audio`, not `ids or links from fish.audio`) and the third `?` (`ztts-help-fish-model-ids`); "two `h3` sub-blocks" matches no markup; `fishspeech.baseURL` cannot read `http://localhost:8080` on a profile with its own address.
