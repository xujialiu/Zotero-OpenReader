## Restoring a Document voice also rewrites Zotero's voice memory (2026-11-18 22:15)

Static inspection of 1.17.1 (`f924aca`): Global default voice, Document
voice, and favorites are plugin settings and are backed up and synced.
The remembered Provider/Language entries are in Zotero's
`reader.readAloudVoices` instead, outside the plugin backup and sync set.
They share a base-language entry with speed, not one entry per regional
Language (`src/core/read-aloud-speed.ts:15–22`).

That preference is not a history of explicit picks. When the adapter
restores a Document voice without a new pick, it calls `planSync` and
writes the result (`src/read-aloud/memory-sync.ts:465–510,1013–1019`).
The plan sets the voice and, if its Provider is known, replaces that
Provider's remembered voice and moves its entry last
(`src/read-aloud/read-aloud-memory.ts:284–307`). Two documents with
different voices of the same Provider and base language can therefore
change that remembered entry merely by taking turns starting reading.

The README's Provider bullet that says returning to Kokoro brings its
voice back predates [ADR 0020](../docs/adr/0020-an-entry-or-language-pick-selects-no-voice.md).
A Provider or Language pick in the Player leaves the voice empty until
the user chooses it. Restoring a Document voice is a different action.
This was checked against the repository, not by toggling the plugin in
running Zotero. Issue #217 concerns publishing the native voice list on
shutdown, not restoring or migrating the native voice preferences.

## Staging the native list still waits for browser voices, and a native pick can start reading (2026-11-18 23:02, issue #261)

Read the installed Zotero 10.0.9 bundle without opening a profile or
running Zotero. `ReadAloudManager.loadVoices`
(`resource/reader/reader.js:82376–82388`) awaits both the remote response
and `BrowserReadAloudProvider.getVoices`. If browser voices are allowed
but the initial `speechSynthesis.getVoices()` is empty, the latter waits
for `voiceschanged` or a 3,000 ms timeout (39719–39744). Staging
`loadVoices` on an unused receiver with an already prepared remote
response therefore still makes the usable list wait for browser voices
the plugin would discard.

`_prepareReadAloud` (84343–84356) starts `loadVoices` without awaiting
it, restores the native preference, and loads the Document analysis.
`startReadAloudAtPosition` (84312–84342) sets the target and opens the
popup before calling it. An open popup activates once a voice resolves,
even with no additional Play (83943–83952). Separately,
`_persistCurrentVoice` (82453–82465) calls `_setReadAloudVoice`
(84357–84402), whose idle branch can also activate. It writes the voice,
tier history, and speed together via
`chrome/content/zotero/xpcom/reader.js:1742–1753`. Catalog publication
alone is therefore not permission to start reading, and blocking only
the native preference write does not block the idle activation.
