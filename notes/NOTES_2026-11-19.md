## Hand-back must close the Player before restoring native voice resolution (2026-11-19 00:04, issue #261)

The native-manager fixture in `test/read-aloud/voice-catalog-flow.test.ts`
left a Player open while bringing the manager back to native voice
resolution. After deactivation, a queued native state notification
activated the voice still held on the manager before the native list
arrived. The disposed catalog voice could no longer supply a controller.
Restoring the original interface alone does not remove the object held
as the selected voice. Opening on a new native voice automatically
would also risk spending credits. The hand-back closes the Player,
clears the projected voices, then restores the native interface and
methods. The retained Position does not require a retained Player.

Zotero 10.0.9's hidden popup sends both system playback actions and its
silent audio element's `playing` event through the same callback
(`resource/reader/reader.js:38310–38340,38562–38578`). The callback
calls `manager.play()` directly. A late callback for the paused doc
does not supersede another doc's pending Play; normal media actions
remain on the existing path when no other document is waiting.

The evidence above is source inspection and the pinned manager fixture,
not a real Zotero verification result.
