## Reading and preview reuse the same Fish Speech reference across servers (2026-11-22 00:48, issue #222)

Two servers can both list `bella` and return different audio for it.
Before the fix, repeating the sentence on B returned A's bytes without a
request to B. The second preview in the same settings window also played
A's bytes. Including the effective Fish Speech endpoint in `audioSetup`
fixes both caches. The provider strips a trailing slash and `/v1` when
addressing its routes, so equivalent spellings share their audio.

## A reader can disappear between startup and a diagnostic or shutdown (2026-11-22 00:48, issue #218)

With a gone window listed before a live reader, the voice-switch report
threw, three other diagnostics returned misleading rows, and disabling
the plugin logged a dead-object error. The speed observer still reached
the live manager but logged the same error. Each diagnostic now keeps
the original row order. Requests for an explicit reader index continue
to address that slot. The memory sync takes a fresh live-reader list
for each walk, including manager lookup and shutdown. Its legacy
cross-document voice spread only runs without a document-key adapter.

## A Play also checks the other readers (2026-11-22 03:35, issue #218)

On Zotero 10.0.9 with a gone window next to a live tab, Shift+Space hit
the dead reader twice, through preparation and the subsequent start.
Both stacks reached `reading-start.ts`'s `takeOver`. Its per-reader
catch let the walk continue. The regression test reached the original
start and paused the other live reader even before the fix, while logging
a dead-object error. Giving Reading start the live-reader supplier removes
that error. The observed idle manager is a separate observation.
