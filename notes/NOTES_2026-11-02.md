## Zotero 10.0.7's Play calls the controller's `clearFailures()`, which the Engine lacked, so no paused reading resumed (2026-11-02 11:47, issue #238)

Reported by two users after updating to Zotero 10.0.7, and reproduced on
1.16.16-beta6: once a reading is paused, the Player's Play and Shift+Space
turn the button to Pause and nothing plays. Each press logs
`this._controller.clearFailures is not a function` at
`resource://zotero/reader/reader.js:82616`.

**Zotero's side** (10.0.7 `resource/reader/reader.js`).
`ReadAloudManager.play()` (82608-82620) now runs, for an active manager,
`this._paused = false`, then `this._controller.clearFailures()` (82616),
then `this._controller.paused = false` and `this._stateChanged()`.
`togglePaused()` (82628) goes through it. The base `ReadAloudController`
has a no-op `clearFailures()` (39392); `RemoteReadAloudController`'s
(40287-40293) clears `_failedIndices` and a set error and dispatches
`ErrorCleared`. It came with zotero/reader 7e50c4622, "Read Aloud: Retry
failed segments on Play" (2026-10-28): before it, Play on a segment that
had failed errored again at once. `activate()` (82600) does not make the
call, so a fresh start (Player closed, then Shift+Space) worked
throughout, near where the reading stopped.

**Why it looked like playing.** The throw lands after `_paused = false`
and before the controller is unpaused or the state pushed: the manager
read `paused: false`, the Engine session `paused: true`, `playing: false`,
`playbackTime` fixed. Measured with trusted Shift+Space presses on a
fixture-a.pdf copy (System Samantha, volume 0): 3 of 3 red. A no-op
`clearFailures` defined on that tab's controller object alone turned the
same press green (`playing: true`, audio `running`, `playbackTime`
0 → 0.379).

**The excerpt is the seam.** Between 10.0.3 and 10.0.7 the four sections
of the manager excerpt the Engine's tests run differ by exactly those two
lines (10.0.7 lines: lang 37967-38091, voice 39268-39316, remote voice and
provider 40478-40590, manager 82204-82805). Every other controller member
the 10.0.7 manager uses already existed on the Engine's controller. The
tests ran 10.0.3's excerpt, so nothing went red when users updated;
diffing those sections against each new Zotero's bundle is how the next
added call is caught before users find it.

**Two probe facts.** A fixture session paused before its first sentence
has no `activeSegment`, and `diagnostics.autoScroll()` then reports
`viewport` and `sentence` null: play a moment before measuring a Follow.
Shift+Enter while paused was fine on 10.0.7, with focus in the document
and with focus on the Player's own Play button (a trusted key into the
Player frame's window): the view returned and the reading stayed paused.

## Zotero's hidden popup replays Play when a request fails faster than its silent audio starts (2026-11-02 12:38, issue #238)

Found by the tester on 1.16.16-beta7, Zotero 10.0.7: against a closed port
(a request failing in ~20 ms), the first Play after an error asked the
server twice, `store.requests` +2; every later press, a press ~0.1 s after
the failure, and every press against a 300 ms failure asked once.

The popup Zotero still mounts behind the Player keeps a silent
`<audio loop>` in step with the manager for the OS media keys
(`useMediaControls`, 10.0.7 reader.js 38274-38385). Its `pause` listener
calls `onSetPaused(true)` (38317-38321) and its `playing` listener calls
`onSetPaused(false)` while the popup thinks it is paused (38322-38326);
both reach the manager. Play unpauses the manager and the element starts
~40 ms later. If the request has failed in between and the `Error` handler
has paused the manager again, `playing` calls `manager.play()` a second
time: `clearFailures()` and one more request, which fails too, then the
element's `pause` pauses the manager. Probe trace (`manager.play` and
`pause` wrapped, the element's events logged; ms from the run start):

```
2516 manager.play   by the test
2530 request 2      error null, session and manager unpaused
2555 request 2      error network, manager paused
2557 audio play     manager.play by the popup (38575 <- 38324 <- 38322)
2560 audio playing  manager.pause by the popup (38573 <- 38319 <- 38317)
2563 request 3      error null, paused
2571 request 3      error network
```

Zotero's behavior, not the Engine's, and harmless: one extra request to a
server that is refusing at once. A live count of Play's requests is taken
against a slow failure. The same listener pauses the Engine session
10-25 ms after any error, through the manager.
