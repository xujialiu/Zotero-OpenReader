## An entry or language pick is a draft beside the manager, and a pending switch is the Player's voice (2026-10-22 00:46, issues #224, #225)

Until #224 the Player's entry and language picks called the manager's
`selectTier` and `setLanguage`, and both resolve a voice at once. In the
10.0.3 manager (`test/fixtures/engine/read-aloud-manager-10.0.3.js`)
`setLanguage` clears `_voiceID` and runs `_resolveVoice`, and `selectTier`
takes `_persistedVoices.tierVoices[tier]` and then `_resolveVoice`, whose
fallback is the tier's or language's remembered voice, else the first of
the region, else the first of the language. While playing, voice-pick.ts
ran that resolution as a dry run and sent the voice it landed on through
the Handoff. The fields were put back, so the Player's three fields kept
the old choice until the takeover. That is what the owner saw as "the
first voice, after a while".

What the build found:

- **There is no way to keep an empty voice inside the manager.** Every
  voice-list landing (`loadVoices`), every `applyPersistedVoices`, and the
  memory sync's restores run `_resolveVoice` again. So the pick is a draft
  kept beside the manager (voice-pick.ts `choose`), which keeps its voice,
  paused, until a voice of the draft is picked.
- **A fresh selection needs the fields set first.** `_applyVoice` drops a
  voice that is not in `voicesForLanguage`. That getter filters by
  `_selectedTier` and by `_lang` plus `currentVoiceRegion ?? _region`.
  For `zh-HK`, `currentVoiceRegion` is none (`normalizeLanguage` drops
  `HK`), so `_region` must say `HK`. The commit writes `_selectedTier`,
  `_lang` and `_region` from the voice and then calls the manager's own
  `selectVoice`. While paused, the rebuild binds the Engine `started`,
  and the Engine asks nothing before Play.
- **`deactivate` already carries two own-property hooks**: the memory
  sync's lifecycle hook and the live voice list's. A third shadow, undone
  out of order, could put back a hook that had since been replaced. So the
  draft ends when it is next read (`draftOf`): a manager that was active
  and is no longer has stopped. Each of its four refusing shadows (`play`,
  `retry`, `jumpTo`, `repositionTo`) asks `draftOf` first, so an ended
  draft never refuses a later Play.
- **One engine test used `selectTier` to start a switch** (#140: a refused
  Zotero voice switched to while reading). It now picks the Premium voice
  itself.
- **The Player page's test DOM gave the pickers no `dataset.pick`.**
  `openPicker(button, undefined)` still listed the voices, because
  `choices()` falls through to `voices` for an unknown key. So every voice
  list test passed by accident, and the first provider-list test failed.
- **A cancel the user asked for and one they did not look the same to
  the Handoff.** Both reach voice-pick.ts as `cancelled`. A `WeakSet` of
  handoffs called off on purpose tells them apart: a newer pick, a re-pick
  of the voice reading, an entry or language pick, a detach. The others
  become `called-off` for the Player's notice. So does a switch dropped
  when `bind` sees other sentences: the parked switch's cancel in
  `keptSwitch`. A cancel after the commit, from `watchStart`, stays quiet.
