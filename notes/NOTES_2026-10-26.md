## Cleanup checks must follow the last observer-triggering write (2026-10-26 14:28, issue #232)

Review of #232's repaired offline kit found another false cleanup PASS.
The script restored the native voice map and checked it immediately, then
restored Global speed. The real memory-sync observer on
`readAloud.speedPercent` calls `spread` and `setDefaultSpeed`, which writes
speed into the native language entries (`src/read-aloud/memory-sync.ts`,
339–352 and 368–379; `src/read-aloud/default-speed.ts`, 50–65). The earlier
native-map check stayed true even though that subsequent write changed
its value. Cleanup marked the run cleaned without rereading the map.

The reproduction executes the actual cleanup script over a Gecko-pref
stand-in with synchronous observers and the real memory-sync module.
Three consecutive runs failed in about 0.2 seconds each. A single native
entry without a speed and a temporary Global speed change suffice: no
fixture import, Player, second language or JSON whitespace is needed.
The native map matches immediately after its restoration, changes during
the later speed restoration, and its immutable snapshot remains unchanged.
Turning Global speed off removes the mismatch. This is a cleanup ordering
fault, not a defect in the production speed propagation.

The cleanup now restores System and speed before the native map. System
can queue a live voice-list refresh (`src/index.ts`, 2661–2672); the kit
observes `diagnostics.liveVoiceList()` rather than requesting another list.
Two quiet samples separated by an event-loop turn are required within
five seconds. A still-loading or unknown result retains recovery state
and reports failure, not successful restoration. The native map, pulse
and memory are then restored, with memory last.

Every captured preference is reread in one synchronous final audit after
all restoration writes and awaited diagnostics. Value, type and user-value
presence must match, and owner Document voice records are checked again.
A failed cleanup retry clears a prior successful marker without replacing
its snapshot. It does not repeatedly replay writes to defeat observers or
silently adopt the new values.

Regression coverage includes the original fixture, the one-entry
reproduction, Global speed off, default-only preferences, a queued
refresh, unknown/loading statuses, and late changes to every snapshot
field before the final audit. This is offline evidence only: no live
profile or installed plugin was changed, and no new live replay is claimed.
The final audit establishes the state at its return boundary, not a promise
against unrelated future user or background changes.
