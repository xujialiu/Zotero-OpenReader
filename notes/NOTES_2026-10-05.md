## The WebDAV folder gets a switch, and an http:// address a warning instead of a refusal (2026-10-05 22:05, issues #172–#175)

PR #171, an automated contribution, made `normalizeWebDAVURL` throw
`WebDAVError('config')` for any `http://` address that
`isLocalAddress` did not call local. Read against the code, it would have
done more harm than good, and ADR 0015 records why it was closed:

- A `'config'` error is the one kind the settings sync and the settings
  auto-upload do not retry on their timer (written for a blank URL, so it
  does not log once a minute forever). An existing `http://` user's sync
  would have stopped at the update and stayed stopped, reported only in
  the log and the pane's status lines.
- `isLocalAddress` is the settings sync's rule for which provider
  sections to hold back, and it leans to *local*: an unparsable address,
  a dotless host, `.local`, 100.64/10 all count. As a gate on sending a
  password in the clear it lets those through and refuses Tailscale's
  `*.ts.net`, which is encrypted underneath.
- `Authorization` goes out only with a username, but the files the
  folder receives — the shared settings and the per-machine backup — hold
  every API key either way, and the backup the WebDAV password too.

What was built instead (issue #172, the switch in #173):

- `webdav.enabled`, run like a provider's switch by `ui/webdav-rows.ts`:
  Enable runs `client.check()` and commits only on a pass, the folder's
  three inputs locked while it is on (`#ztts-webdav-folder input`, the
  password through `setSecretLocked`). Disable needs no reading guard.
- One gate, `webdavSwitchOn(webdav, key)`: the two positions transports,
  `canPullShared` and `pullBeforePlay`, the auto-upload, the settings sync
  and the pane's two status lines read through it. The two switch
  observers in `src/index.ts` are now pairs, the second on
  `zotero-tts.webdav.enabled`, so enabling the folder pokes the
  transports as ticking their box does. The auto-upload needs no new
  observer: its keys are every `DEFAULTS` pref, the switch included.
- The upgrade, `migrateWebDAVFolderSwitch`, a startup step before the
  transports: a set `webdav.url` turns the folder on, once, behind the
  undeclared marker `webdav.enabledMigrated`. A marker because Gecko
  drops a user value equal to the default, so after a Disable
  `prefHasUserValue('…webdav.enabled')` is false and the pref looks never
  written; test/index.test.ts's #161 test, which sets a URL and no
  switch, passes through this step.
- A server-copy button's `finally` repaints the rows: a restore from the
  server runs inside the `busy` flag, so the `refresh()` its
  `onRestored` asks for is skipped there.
- `diagnostics.positionSync()`, `settingsUpload()` and `settingsSync()`
  report `folder`; their `enabled` is still the switch under it.
- A restore checks the folder beside the providers (issue #175): the
  pane's `verifyProviders(restored)` runs `providerRows.verifyEnabled()`
  and the rows' `verifyEnabled(restored['webdav.enabled'])` together.
  Unlike a provider's, the folder's switch is never written on by the
  restore: `applyBackup` writes `webdav.enabled` false, and only a passing
  check turns it on. Written straight, the new switch observers poked the
  syncs at the restored address before its check had run — the review of
  ad03bc8 caught it. A file without the switch re-checks the folder as it
  was, off meanwhile, since its address may have changed under it.
  `parseBackup` adds `webdav.enabled: true` to a pre-switch file that
  holds an address, the upgrade's rule.
- The rows' `verifyEnabled` is not held back by `busy`, since a restore
  from the server calls it from inside its own button, but by `checking`:
  a folder an Enable or Test connection is already checking is left to
  it, as `provider-rows.ts` leaves a provider mid-check. Enable commits
  only when the address, username and password are still those it
  checked, so a restore from a file during its check cannot be turned on
  unchecked.
- `diagnostics.sharedSettings()` and `settingsFiles()` still reach the
  folder while it is off: they are the owner's and the tester's way of
  reading it, not a use.
