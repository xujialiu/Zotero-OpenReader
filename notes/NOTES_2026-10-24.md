## An idle draft's region reset needs the just-written native voice entry (2026-10-24 19:51, issue #232)

The full-path test prepared for the ownership refactor (#231) found an
existing selection failure on unmodified commit `0698f24`. With an
unavailable Document voice, an inactive Player, and a Provider/Language
draft, selecting Jenny ended on Aria and saved Aria as a manual Document
voice. The pinned manager became active without an error. The request in
this reproduction was fake audio, not real provider traffic or a charge.

The draft stages the selected voice's region before native `selectVoice`.
The inactive branch of `_setReadAloudVoice` then calls `setLanguage(lang)`
without that region, before its restore and activation. In the pinned
Zotero 10.0.3 manager, `setLanguage` clears the region and resolves again
(`test/fixtures/engine/read-aloud-manager-10.0.3.js`, 470-493); the stale
`_persistedVoices` can resolve to another voice. #183's in-flight override
runs at the later restore, after that replacement, so it sees and saves
the wrong voice. Its direct native-pick tests do not cover this draft
commit ingress.

The narrow repair is in memory-sync's existing pick hook. A nonpersisting
`setLanguage` nested in an explicit Document voice pick on an inactive
manager loads the native language entry that `_setReadAloudVoice` has
already written. `loadEntry` reads the current pref, not the potentially
lagging reader state, and clones the entry into the reader compartment.
No Document voice is written early; normal post-pick persistence remains
responsible for the manual record. Active picks, previews, restoration,
identity-less adapters and the native idle activation policy are unchanged.

All three new full-path regressions fail on the original source and pass
with that preparation: nonfirst US English with Global speed on or off,
and a second Hong Kong voice where native normalization drops the region
and the old path selected Mandarin. The larger original fixture also
passes with only this source change. The tests run the real Player,
voice-pick, memory, provider tiers and Engine over the pinned manager and
synchronous pref observers, with virtual audio. This establishes the
selection/persistence mechanism; live realm behavior and perceptual voice
quality are separate checks, not implied by the fixture.

## A trailing dot names another pref; type and user flags do not prove restoration (2026-10-24 22:05, issue #232)

The live kit read a full preference name through `getBranch(name + '.')`
and an empty leaf. That reads a different trailing-dot preference. It saw
no native voice map although the real map had ten lanes, and captured
`none` snapshots while muting the correct volume leaf. Comparing only
type and user-value flags then produced a false cleanup PASS. Exact leaf
names, values and flags must all be checked; a registered default with no
user value is not a missing preference.

The tester also ran the old installed beta before installing beta2, an
accidental pass rather than an authorized comparison. The fixed beta2
bundle did show a nonfirst System Ava in the manager, Player, saved manual
record and correctly read native entry. Its commit-window console entries
were autoplay-gate warnings, not evidence that the choice was refused;
two source-less install-window exceptions remain unattributed. The
paused-active control was not repeated live. The 30-minute run timeout was
followed by recovery-only work, not another synthesis pass.

The true old volume and native English entry could not be reconstructed.
Clearing System and inferring the notification pulse were not captured
restoration either. The owner explicitly adopted a new baseline instead:
volume 19/user, System true/user, native English history Ava and pulse 208
retained. A bounded operation at 2026-10-24T13:24:31Z made only the two
requested preference writes and verified native-map, document-record,
default and memory hashes unchanged across them. Both test attachments
were removed; 79 owner Document voice records matched and Position row
count returned to 78. Row-count equality is not a comparison of all row
contents. No owner Player was operated, and WebDAV stayed off.

Reusable scripts no longer contain the one-off recovery's hardcoded
values. The read-only baseline now gates the exact build, immutable
snapshots precede mutation, cleanup refuses incomplete or corrupted
snapshots and owner identities, and restoration checks value/type/user
presence including default-only strings. Missing evidence fails closed;
it is never replaced by a new snapshot or guessed counter. Offline tests
execute the actual scripts over a fake Gecko preference/reader interface.
The repaired revisions were not replayed live, and their offline checks
must not be presented as a fresh end-to-end live PASS.
