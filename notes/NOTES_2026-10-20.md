## A connection check must keep its settings through the committing continuation (2026-10-20 16:41, issues #214, #215, #216)

The current release, 1.16.12 at `9a0a671`, still reproduced the three
settings-pane failures. The issue's deferred real connection check reached
`good.example`, yet Enable committed `typo.example` after an edit while its
synthesis reply was held. The pane kept Disable after the real refusal
handler switched Premium off, and Fish's Manual IDs field became editable
after Test connection, a failed Enable or the account-only repaint.
The initial three reproductions gave the same five failures and three
passing controls in three consecutive runs, about 0.32 seconds each.

An additional direct-pref write proved why disabling inputs is not enough:
that write still changed the checked settings while the request was held.
Rejecting a changed configuration at the check boundary fixed both forms
in the experiment. Repainting on the enabled pref fixed the stale tier
button; reapplying the source restriction after a generic unlock fixed
all three Fish paths. These were local tests with controlled dependencies,
not a live Zotero pass.

The permanent seam is `test/ui/prefs-pane-state.test.ts`: the real
`onPaneLoad`, real connection check and real refusal handler, a small fake
document, synchronous Zotero-style pref observers, and no external
network. Before the implementation, it and the added provider-row cases
failed 19 assertions while 34 controls passed. The full suite after the
implementation passes 3,239 tests in 172 files. Both Standard and Premium
are covered for used-up and daily-limit refusals.

`provider-rows.ts` now owns the enabled-or-checking lock, including secret
reveal buttons. A check captures only its provider's effective settings
and blocked reason. Its return is evaluated in the caller's continuation,
immediately before acceptance: comparing before the last `await` would
leave one more microtask window in which a pref write could make a checked
result stale. A deterministic test writes in that window. Settings and
credentials in the snapshot remain inside the closure and are never
logged. A changed configuration gets a check-again message, not an
automatic retry. A stale restore failure cannot turn off a newer
configuration, and its summary cannot claim every provider was checked.

Enabled-pref observers repaint external changes. Own writes suppress only
those observers' duplicate callbacks; existing button and restore refreshes
keep their original behavior. External catalog and credits refreshes wait
one microtask and are coalesced, so a synchronous restore's switch writes
do not list a half-written section. Pane unload removes observers and
button listeners, and late checks no longer write settings.

Fish source and Model commands use the same lock as the provider rows.
Every generic unlock reapplies the Manual voices restriction through
`onUnlocked`; source observers cannot unlock a section that is still
checking. `test/ui/fish-provider-state.test.ts` runs the real three row
modules together and covers observer-driven repaints and synthetic
commands while the check is held. Saved manual IDs are not erased.

The four Biome error-level diagnostics in `prefs-pane.ts` are unchanged
baseline `forEach` callback-return lint findings; TypeScript passes.
No new configuration or preference is introduced. The user-facing cost is
that one provider's fields cannot be edited while its check runs; other
sections remain available. Live verification is pending on
`1.16.13-beta`, using the provider-controls, Zotero-tier and Fish-source
cases rather than the whole checklist.
