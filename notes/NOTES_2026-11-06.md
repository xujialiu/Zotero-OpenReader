## Overlapping initial segment requests consume the shared target twice (2026-11-06 00:26, issue #234)

The follow-up tester inspected the installed 1.17.1-beta4 on Zotero 10.0.7,
with the WebDAV folder off and no server requests. Direct starts at a known
Han SDT point were correct in the retained controls. Injecting one
`applyPersistedVoices` at `_requestReadAloudSegments` entry produced the
wrong final segment twice. In the retained raw result, the first
`setSegments` chose index 7 / `[6,0,0]` / `前文你好后文。` at 59.58 ms;
the second chose index 10 / `[7,0,20]` / `Yes.` at 78.20 ms. The target
`[6,0,2]` was consumed once, then returned null to the other continuation,
which used the saved position. This proves a real failing interleaving, not
which spontaneous trigger caused each earlier observation.

In the installed `resource/reader/reader.js`, `activate` (82601) and
`_applyVoice` (82580, while active with no segments) both request segments.
`_requestReadAloudSegments` (84105) awaits `_loadSDT`, then
`_captureReadAloudStart` (84133) chooses selection, a one-shot target, or the
saved/visible position before `setSegments` (84127). There is no pending
request gate. The two continuations build different segment objects, so
`_createController`'s identity-based active-segment preservation (82705)
does not prevent the second result from replacing the first.

`segment-preparation.ts` wraps initial preparation only, per internal reader.
An active manager with no segments shares the native request already in
flight, rather than consuming the target again. After completion, a queued
request is retried only if the active manager still lacks segments and has
a granularity: the old request may have been invalidated, or the player
closed/reopened just before its pending marker cleared. Once segments are
installed, native selection/recomputation behavior is unchanged. A rejection
clears the pending marker and is reported; disposal/dead readers cannot
launch a queued retry. The reader receives its original promise, not a
sandbox promise. `diagnostics.segmentPreparation()` reports started,
coalesced, retried and pending counts per live reader.

The regression uses Zotero's existing native-manager fixture plus a new
verbatim excerpt of the installed request/capture methods. The excerpt
retains the Corporation for Digital Scholarship's AGPL copyright notice;
it is test-only and is not code to copy into OpenReader. The red test ran
the actual `applyPersistedVoices` -> request -> target consumption ->
`setSegments` chain and got `[7,1]` instead of `[7]`. Fifteen tests now cover
the fix, its native failing control, synchronous reentry, native promise
identity, granularity invalidation, reopening on both sides of completion,
per-reader isolation, rejection, disposal and dead-window handling.

The earlier kit also needed fail-closed safety gates before reuse. Five of
six initial inert-boundary restoration tests failed on its old script 62.
The revised script requires verified store/server cleanup, exact preference
names, all four transports quiet, and every named preference restored before
it enables anything. Reading memory is the last reading preference; the
folder is the final network gate. Document-voice records are compared by
content, the run's new record is removed, and independently changed records
are not overwritten. Seven kit tests pass, including the added document
record control. Server snapshots require the dedicated destination, both
files present and the fixture absent; destructive cleanup is scoped by
library and attachment key. The updated scripts still require a live run.

The research report's broad restoration claim is narrowed by its raw result:
`r91-restore.js.json` reports `ok:false` after its final tab-selection check
threw. Earlier fields do prove the same bundle, zero fixture rows, baseline
in-memory counts, unchanged readers, restored volume/memory/debug state and
quiet transports. Its folder-pref inspection used the wrong namespace;
`diagnostics.positionSync().folder:false` is the actual folder evidence.
The next verification must audit the exact plugin-pref names and prior
fixture document-voice residues rather than inherit that report's verdict.
