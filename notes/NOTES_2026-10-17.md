## A pick on an idle manager was restored over by the Document voice from before it (2026-10-17 20:28, issue #183)

Zotero persists a Player pick through `onSetVoice` into the reader's
`_setReadAloudVoice` (11.0-beta.1 `resource/reader/reader.js`
88538-88585; the 10.0.3 excerpt in `test/fixtures/engine/` is the same
flow). On an inactive manager that method does more than write the pref:
its branch at 88576-88583 runs `setLanguage(lang)`, then
`_syncPersistedVoicesToManager()`, then `activate()` when a voice is
selected, all inside the pick (`selectVoice`, `selectTier`, `setLanguage`
with `persist`). The memory sync runs a restore at two of those steps: the
`_syncPersistedVoicesToManager` wrapper's `apply()`, and the `activate`
hook's `resync`. Both read the document's voice from its record, and
`notePick` writes the pick into the record only once the pick has
returned. So both restores planned the voice from before the pick.

Measured in the issue's repro, instrumented, a Jenny pick with the
Document voice `local::af_aoede` unlisted: the entry got
`voice: azure::en-US-JennyNeural` from `_setReadAloudVoice`, then
`voice: local::af_aoede` from `apply` under the wrapper, with `planSync`
moving the `kokoro` key last in `tierVoices`. `applyPersistedVoices` then
missed the voice, and `_findFallbackVoice` (84902-84944) took the last
`tierVoices` key as its target tier, found it empty, widened to the whole
language and took the first voice of the region: Zotero's own tiers first
in the merged list, then the plugin's sorted by label. With Zotero Standard
listed, an Azure Entry pick ended active on `standard-ava`; without it, on
Aria. The activation guard let it through on `picking`, and `notePick`
saved the fallback as a manual Document voice. A language pick was lost
the same way (the manager went back to `en`).

The window opens only on an idle manager with the Player open. With an
available voice, Zotero's auto-activation (`_onReadAloudEngineStateChanged`)
has made the manager active before the user can pick, and an active
manager's `_setReadAloudVoice` runs no restore. The states that leave it
idle are the unavailable-voice guard (#146, #179) and no voice at all; with
no voice at all `documentChoice` is null and the restore plans no voice,
which is why the control case always kept the pick.

The memory sync now records, per manager (waived), a pick in flight: set
by the pick shadow outside its own moves (`applying`) and outside a
Handoff preview. While it runs and the manager is idle, `documentChoice`
answers the voice the manager has landed on, so both restores plan the
pick and leave Zotero's entry as `_setReadAloudVoice` wrote it. An active
manager keeps its session's voice. `test/read-aloud/document-voice-pick.test.ts`
runs Zotero's own manager with the real memory sync and provider tiers in
`index.ts`'s order.

## The memory sync's lifecycle hooks hid every later shadow of `activate` (2026-10-17 20:41, issue #189)

Since #146 the memory sync puts `activate`, `deactivate` and
`_createController` on each manager as own properties, and each hook ended
in the function it had read off the manager at attach: the prototype's.
The speech text settings shadow `activate` on the same prototype, and
attach after the memory sync at all three sites (`index.ts` 543 then 579,
799 then 812, and the startup steps at 2688 then 2711). Zotero calls
`activate` through the instance (11.0-beta.1 `reader.js` 88119 and
88582), so the own property won, and its captured function skipped the
shadow. The shadow's snapshot refresh never ran; the snapshot was filled
once, lazily, at the tab's first request, and kept for every later Reading
session in that tab. Swapping the two attach lines turns the issue's repro
green, which is how the order was confirmed as the cause.

The hooks now take the method as it stands at each call: an own one found
at attach, else `ownerOf(target, name)` at that moment, the shape
`attachMoveHook` already used for `_resolveVoice`. The general lesson: an
own-property hook that delegates to a function captured from the prototype
hides every prototype shadow added after it, in whatever order the modules
attach. `test/read-aloud/bracket-pairs.test.ts` now attaches the two
modules in `index.ts`'s order.
